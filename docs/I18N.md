# I18N.md — Hindi-First Locale Architecture

## Locales
| Locale | Role |
|---|---|
| `hi-IN` | Default, first-visit locale |
| `en-IN` | Secondary |

## Behavior
- First visit → Hindi, regardless of browser language (owner requirement).
- Switcher: `हि | EN`, persistent, ≥ 44×44 px, `aria-pressed`/`role="group"` semantics, `lang` attribute updated on `<html>` and on swapped text.
- Switching does **not** reload the page and does **not** reset scroll position.
- Preference stored (e.g., `localStorage`) **only after an explicit user change**; wrapped in try/catch for private modes.
- URL strategy (choose and record in `DECISIONS.md`): single URL with client-side switch (preferred for shared link simplicity) or `?lang=en` for deep-linking English to specific guests.

## Dictionaries
```
src/i18n/hi.ts
src/i18n/en.ts
src/i18n/types.ts   // shared key type; build fails if a key is missing
```
- Keys by purpose (`hero.invocation`, `invite.message`, `events.tilak.title`).
- No string concatenation for sentences; use whole strings or ICU-style templates.
- Hindi strings reviewed by a native speaker before launch.

## Dates & numbers
- Store ISO date-only strings; format with `Intl.DateTimeFormat`.
- Use `hi-IN` / `en-IN` locales; verify Devanagari month names render as intended ("नवंबर", "दिसंबर").
- Decide numeral style (Latin digits as in confirmed copy: "25 नवंबर 2026") and keep consistent.
- Countdown numerals follow the same rule.

## Fonts
Hindi uses Noto Serif/Sans Devanagari; English pairs a Latin serif. Ensure `font-family` fallbacks per locale and `lang`-specific line heights.

## Metadata
`<html lang>` updated; Open Graph `og:locale` = `hi_IN` with `en_IN` alternate; OG image text is Hindi (रचना × उदित / शुभ विवाह / 2 दिसंबर 2026).
